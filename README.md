# LAN Review · 局域网提审、审核与交付工具

给内容创作者用的三件套：**创作者电脑**（macOS / Windows / Linux）+ **手机或笔记本浏览器审核** + **笔记本接收成片**。
全部只在你的局域网里工作：不需要联网、不需要账号、不上传任何文件到公网。

界面本身已经写清楚了每一步该做什么，这份说明只补充"怎么开始"和"出问题怎么办"。

---

## 一、开始使用（创作者电脑）

1. 安装 [Node.js LTS](https://nodejs.org/zh-cn/)（只需一次）。
2. 双击对应系统的启动文件：
   - macOS：`启动-macOS.command`（第一次若提示无法打开，右键该文件 → 打开）
   - Windows：`启动-Windows.bat`（防火墙弹窗请点**允许访问**）
   - Linux：`启动-Linux.sh`
3. 浏览器会自动打开创作者页面。第一次会让你选一个**工作区文件夹**（所有项目和记录都放这里，之后会记住）。

> 程序运行时保持那个黑色窗口开着；手机正在审核时不要关。关掉窗口=停止程序，所有记录都还在，下次双击继续。

## 二、日常流程

```
选择工作区 → 新建/选择项目 → 选待审文件 → 连接审核设备 → 提交 V01
→ 看反馈 → 改完提交 V02 → 等审核通过 → 选接收电脑 → 正式交付 → 查看结果
```

页面上方有一条实时的流程进度条，会告诉你现在卡在第几步、下一步点什么。

### 让手机/笔记本参与审核
1. 创作者页面 → **设备连接** → 选"审核设备" → 生成配对码。
2. 手机相机扫二维码（或让对方在浏览器输入页面上显示的局域网地址，再填 6 位配对码）。
3. 回到创作者页面，在"等待允许的设备"里点**允许**。
4. 之后在"本次提审"里勾选这台设备再提交，对方的浏览器里立刻出现任务。

审核者可以：预览图片/视频/音频/PDF/文本、下载不能预览的文件、按文件写意见、
在播放到某一秒时点"标记此刻"留下时间码意见、给出"需要修改"或"审核通过"。

### 让另一台电脑收成片
1. **设备连接** → 选"接收设备" → 页面会给出安装包下载页地址（`http://你的IP:端口/get-receiver`）。
2. 在那台电脑上打开该地址 → 下载"接收端安装包" → 解压 → 双击 `启动接收端`。
3. 在接收端页面里选一个保存文件夹，填创作者电脑地址 + 配对码。
4. 回到创作者页面点**允许**。以后每次"正式交付"，文件会自动传到那台电脑并逐个校验。

## 三、几个重要约定

- **提审 ≠ 交付**：提交审核后，完整文件仍留在创作者电脑上，审核设备只是通过局域网查看；不会提前进接收目录。
- **版本不可变**：每次提交都会把当时的文件复制成 `V01`、`V02`… 的快照。之后你继续改工作文件，已提交版本和旧意见、旧结论都不变。
- **只有审核通过的那个版本能交付**，交付的字节就是这个批准版本的字节（两端都会显示校验结果）。
- **未连接/未授权的设备看不到任何内容**；取消授权立刻生效。
- 数据都在工作区里的 `.lanreview/` 文件夹（数据库 + 版本快照）。换电脑时把整个工作区拷走即可。

## 四、出问题怎么办

| 现象 | 处理 |
| --- | --- |
| 手机打不开页面 | 确认两台设备连同一个 Wi-Fi；地址要带 `http://` 和端口；Windows 请放行防火墙（页面"设备连接 → 连接诊断"里有具体步骤） |
| 页面显示"设备离线" | 让对方重新打开审核链接，或让接收端页面保持打开（可最小化） |
| 交付中断/接收端关机 | 交付记录会变成"传输中断"并写明原因；对方上线后点**重试**，已传完的文件不会重传（断点续传） |
| 提示空间不足 | 换个工作区/接收文件夹，或清理磁盘；程序不会假装成功 |
| 文件不能预览 | 页面会说明原因并提供下载；这是格式本身浏览器不支持（如 PSD/HEIC） |
| 忘了工作区在哪 | 创作者页面右上角"工作区"芯片显示完整路径，点"打开"直达 |

## 五、给开发者/维护者

```bash
node server/index.js        # 启动创作者主机（默认 http://127.0.0.1:8780）
node agent/index.js --agent # 启动接收端（默认 http://127.0.0.1:8790）
npm test                    # 单元 + 二维码自检 + 全流程端到端测试
```

- 运行时**零第三方依赖**：只用 Node 内置模块（`node:http`、`node:sqlite`、`node:crypto`、`node:zlib`），所以不需要 `npm install` 就能双击运行。
- 二维码、PNG、ZIP 都是自带实现（`server/lib/qr.js`、`packaging/zip.js`）。
- 测试用的 `jsqr`/`pngjs` 只是 devDependency，用来反向验证二维码可被第三方解码器识别，运行产品不需要它们。
- 目录：`server/`（主机服务与业务层）、`agent/`（接收端进程）、`web/`（创作者控制台 / 审核页 / 接收端页面）、`packaging/`（接收端安装包）、`test/`（测试）。
